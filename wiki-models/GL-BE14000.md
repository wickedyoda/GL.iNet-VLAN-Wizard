# GL.iNet GL-BE14000 — Flint 4

## Device
- Model: `GL.iNet GL-BE14000`
- Board: `glinet,gl-be14000`
- Target: `mediatek/mt7987`
- OpenWrt: `21.02-SNAPSHOT`
- Kernel: `5.4.281`
- Architecture: `aarch64_cortex-a53`
- Hostname example: `Flint4-Home`
- Tailscale example: `flint4-home.tail99133.ts.net`

## Preflight
```bash
ssh -i ~/.ssh/id_ed25519_flint4 -p 122 root@<router> 'echo OK'
```

## Port Layout
- DSA mode
- LAN ports: `lan1`, `lan2`, `lan3`, `lan4`, `lan5`, `lan6`
- WAN: `eth2`
- Trunk uplink: `lan6` often intended as trunk uplink; verify cabling

## WAN
- Primary WAN: `eth2` metric 1
- Second WAN: often `eth1.3` metric 4
- Dual-WAN is common; VLAN wizard avoids WAN ports automatically

## VLAN Layout Example
| VLAN | Purpose | Subnet | Notes |
|---|---|---|---|
| 1 | Primary LAN | `192.168.1.0/24` | Often merged into br-lan or kept native |
| 20 | Guest | `192.168.20.0/24` | Client isolation recommended |
| 30 | IoT | `192.168.30.0/24` | Busiest VLAN on many installs |
| 40 | Testing | `172.23.2.0/24` or `192.168.40.0/24` | Isolated |
| 50 | Work | `192.168.50.0/24` | SQM often desired here |

## SQM / QoS
- If using SQM, enable on a dedicated VLAN bridge such as `br-vlan50`
- CAKE nominal configs often cap well under line rate
- Flint 4 runtime may show a hidden cap versus UCI

## Firewall Notes
- Enable WAN forwarding for each VLAN zone
- Enable DNS leak protection if needed
- Tailscale and WireGuard zones need separate review

## Wireless
- Multi-radio device; wizard adds SSIDs to every detected radio
- If you want per-VLAN Wi-Fi only on specific radios, edit wireless config after wizard run

## Install Wizard
```bash
sh -c "$(curl -fsSL https://raw.githubusercontent.com/zippyy/GL.iNet-VLAN-Wizard/main/install.sh)"
```

## Rollback
- If the network breaks, the wizard keeps a 60-second auto-rollback
- Confirm working within 60 seconds, or let it restore automatically

## Known Flags
- `lan6` may be down if intended trunk port is unplugged
- Double VPN stacks can conflict; review Tailscale/WireGuard coexistence
- DNS path issues may require upstream/DNS leak protection review
